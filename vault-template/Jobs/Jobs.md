# Jobs

Priming notes. Read the matching one **before** doing the job, not after.

Each opens with a **Read first** list naming the exact notes that job needs. Load those and
nothing else. One note hands you the complete method plus only the context that job uses, so
you never bulk-read the vault to write an email.

When the user corrects how you did a job, fold the correction into the matching note here so
it sticks. That is how these get better.

- [[Vault upkeep]] - how to keep this vault useful, and the `vault-doctor` checker.
- [[Daily note]] - the day log in `Journal/`: when to write one, and what belongs in it rather
  than in a project note.

Add your own as recurring jobs show up: meeting notes, client emails, briefings, job
applications. Prompt 5 in `SETUP-PROMPTS.md` writes one for you.
